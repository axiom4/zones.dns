# Changelog

## Unreleased
- Geolocation: every country and network shows its share of the queries answered with an address; the country list has a search (name, code or one of its domains) when there are more than 8; the *Destination addresses* tile says how many are located while some are still pending; the headings show how many countries and networks are listed.
- Statistics: an *Answers* panel splits the queries of the period into *with an address* (the total of the geolocation page), *without an address* (HTTPS, PTR, TXT, an AAAA for a name without IPv6...), *name does not exist*, *blocked* and *failed*, with the share of each; an *Errors* tile next to *Blocked*. New hourly counter `answer` (API: `by_answer`). Hours saved before the update show as *not split yet* until `manage.py rebuild_stats` is run once.
- Geolocation: when the period held hours saved both before and after the update to `GeoStat.first` (migration 0030 without `rebuild_stats`), the older hours counted 0, so the countries and the total were much smaller than the query log. Those hours now count every address, as the note on 0030 says; `rebuild_stats` still makes them exact.
- DNS daemon: a UDP answer is packed once (it was packed to measure it, then again to send it), and dnslib no longer prints two lines per query to stdout (request and reply; only truncated answers and errors are printed now, the query log keeps every query).
- Query log: *Load more* pages by the last row shown (`before=<id>`, keyset) instead of an offset: deep pages read only their own rows, and rows logged meanwhile no longer bring back rows already shown. `count` stays the total of the filters; `offset` still works.
- PostgreSQL: a trigram index on the log names (`qlog_name_trgm`, migration 0031, extension `pg_trgm`) makes the log search fast. Skipped, with a message, when the database user cannot create the extension. On a partitioned log the index build locks writes: migrate at a quiet time.
- Geolocation: a query was counted once per address of its answer (four A records = four), in the total and in every country, network and city, so the numbers were larger than the query log and the statistics and the shares were skewed towards names with many addresses. Now each query is counted once, at its first address (the one the client connects to: new `GeoStat.first` counter), so countries and networks add up to the total; the tile says *Queries answered with an address* (blocked, NXDOMAIN and answers without an address are not counted). Needs `manage.py migrate` (0030) and then `manage.py rebuild_stats` once: until then, hours saved before the update still count every address.
- Performance of the DNS daemon: a warm query no longer touches the database. Every query outside the zones read the DHCP name settings (`Setting`) from the database even with DHCP off: they are now read with the zones when the data changes. The database ping before each query (`conn_health_checks`) is done only after 30 s of idle time. With Redis the change counter is read at most every 0.2 s instead of up to six times per query. The longest matching zone is found with one set lookup per label instead of a scan of every zone. The blacklist memory drops the least recently used names instead of emptying itself at 20000. `main_domain` is cached. With `DNS_DNSSEC=true` the DNSKEYs of a signer zone are kept for their TTL (at most an hour) instead of being asked upstream for every validated answer.
- Query log: `grouped?by=name&ordering=count` failed with error 500 once the hourly counters had rows. The *country* filter is cached for 60 s and limited to the 5000 most asked domains (the limit was documented but not applied). The statistics over more than a day are cached 5 minutes instead of 30 s. Purging old counters updates the totals with one query instead of one per client. The single-column index on `QueryLog.domain` is dropped: the `(domain, time)` index already covers it, and every log row wrote one index less. Needs `manage.py migrate` (0029; on SQLite it rebuilds the log table: do it at a quiet time). README: optional trigram index for the log search on PostgreSQL.
- DNSSEC validation (`DNS_DNSSEC=true`, RFC 4034, 4035, 6605, 8080): validates `RRSIG` records on upstream answers against `DNSKEY` and `DS` records (RSA/SHA-256, RSA/SHA-512, ECDSA P-256/P-384, Ed25519; SHA-1/256/384 DS digests), sets `AD=1` on verified responses and returns `SERVFAIL` on bogus signatures unless the client sets `CD=1`.
- Per-client DNS query rate limiting (`DNS_RATE_LIMIT`, `DNS_RATE_WINDOW`): refuses queries over the per-window threshold with `REFUSED` (logged as `blocked` / `rate limit`).
- Dynamic DNS updates (RFC 2136, `OPCODE=UPDATE`): clients in `DNS_UPDATE_ALLOW` (IPs or CIDRs) can add or delete records with full RFC 2136 prerequisite checking (`YXDOMAIN`, `NXDOMAIN`, `YXRRSET`, `NXRRSET`) and automatic zone serial bump.
- DHCP: `manage.py rundhcp` runs, as set in `.env` or the GUI (`GET`/`PATCH /api/dhcp/settings/`; everything is off by default; turn off the router's own DHCP server first, two servers on one network conflict).
  - DHCPv4 (RFC 2131, 2132, 3046, 3118, 3203, 3396, 3397, 3442, 4388, 4702, 6842): range, router, DNS servers, domain, lease time with T1/T2, fixed addresses by MAC (`DHCP_RESERVATIONS`), clients told apart by their client identifier (option 61, RFC 6842), an address is probed via ARP (`AF_PACKET` on `DHCP_INTERFACE`) and ICMP `ping` before it is offered and one that answers stays out of the pool for ten minutes (`DHCP_PROBE`, RFC 2131 3.1.2), standby failover delay (`DHCP_FAILOVER_SECS`), Leasequery (RFC 4388), authenticated `FORCERENEW` (RFC 3203 / RFC 3118 HMAC-MD5 per-client Reconfigure Key, option 90), offers held a minute, declined addresses kept out for ten minutes, leases that ended a week ago forgotten. Options sent when the client's parameter request list names them: NTP (42), search list (119, RFC 3397), classless routes (121, RFC 3442, default route added), MTU (26), PXE server and file (66, 67), encrypted resolvers of `DNS_DDR` (162, RFC 9463). Relay agents and several networks (`DHCP_SUBNETS`, JSON): the scope is chosen by `giaddr`, the reply goes to the relay on port 67, option 82 is echoed (RFC 3046). Client FQDN (81, RFC 4702) is answered with N=1: nobody updates the DNS, this server does it. A client with no address yet and no broadcast flag gets the reply straight to its hardware address when `DHCP_UNICAST=true` (Linux, `CAP_NET_RAW`, RFC 2131 4.1), else a broadcast.
  - DHCPv6 (`DHCP6=true`; RFC 8415, 3633, 3736, 5007): normal (`IA_NA`) and temporary (`IA_TA`) addresses (`DHCP6_POOL`) and delegated prefixes (`DHCP6_PD_POOL`, `DHCP6_PD_LEN`, `IA_PD`, with optional kernel route installation via `DHCP6_PD_ROUTES=true`) with Solicit, Advertise, Request, Confirm, Renew, Rebind, Reply, Release, Decline, Information-request, Leasequery (RFC 5007), authenticated Reconfigure (RFC 8415 §20.4 HMAC-MD5 Reconfigure Key, option 11/20), server preference (`DHCP6_PREFERENCE`, option 7) and rapid commit; Relay-forward / Relay-reply (nested too, interface-id echoed); DNS servers (23), search list (24), information refresh time (32) and the DNR option (144). Without a pool it is stateless. The server identifier is a DUID-UUID.
  - Router Advertisements (`DHCP_RA=true`; RFC 4861, 8106, 9463): RDNSS, DNSSL, the prefix of `DHCP6_PREFIX` (optional SLAAC) and the DNR option, every `DHCP_RA_INTERVAL` seconds and on a Router Solicitation (not more often than every 3 seconds). Router lifetime is 0 by default: this host does NOT become a default router (`DHCP_RA_ROUTER_LIFETIME`).
  - DNS: the server answers `<client host name>.<DHCP_DOMAIN>` and the reverse name of a leased address from the leases (`DHCP_NAMES`; the query log says `DHCP lease`).
  - GUI: the DHCP page lists the leases (addresses and prefixes, search, ended ones, end a lease) and edits the DHCPv4, DHCPv6 and Router Advertisement settings (`GET /api/dhcp/leases/`, `DELETE /api/dhcp/leases/<4|6>/<id>/`, `GET`/`PATCH /api/dhcp/settings/`). The Django admin has *DHCP leases* and *DHCPv6 leases*.
  - Needs `manage.py migrate` (0023, 0024, 0025, 0026), the right to bind UDP 67 and 547 (INSTALL.md) and `CAP_NET_RAW` for `DHCP_UNICAST` and `DHCP_RA`.
  - Tested: synthetic packets for every message above, ARP probe and L2 unicast frames, and the real UDP sockets on the loopback interface (a DHCPv4 Request got its Ack, a DHCPv6 Information-request its Reply). Not tested on hardware: a physical client or router, the multicast group (ff02::1:2) and the raw ICMPv6 socket of the Router Advertisements.
- DDR (RFC 9462) and encrypted DNS. `_dns.resolver.arpa` is answered here and never goes upstream (the upstream answered SERVFAIL, shown as Error in the query log). `DNS_DDR` (e.g. `dot:dns.example.lan@192.168.1.23 doh:dns.example.lan/dns-query{?dns}`) announces your encrypted resolvers in the SVCB answer (with address hints), so clients that support DDR (Apple, Windows, Android) switch to them; empty (default) = NXDOMAIN. DNS over HTTPS is served by the app itself at `/dns-query` (`DNS_DOH=true`, RFC 8484, GET and POST; it passes the query to the daemon over TCP, `DNS_DOH_BACKEND`); DNS over TLS through nginx (`deploy/nginx/dns-dot.conf`, port 853). `manage.py check_ddr` asks each announced resolver a real query over a verified TLS connection and fails if one does not answer. Limits: DoH has no login, so restrict `/dns-query` to your network (the nginx example does); the query log shows DoH clients as 127.0.0.1 (the daemon sees the app, not the client). DNR (RFC 9463): `manage.py dnr_options` prints, from `DNS_DDR`, the DHCPv4 option 162, DHCPv6 option 144 and IPv6 RA option 144 (hex; `--format dnsmasq` or `--format kea` print only that configuration, ready to save to a file) for your DHCP server or router, so clients learn the resolvers from the network before asking anything; a resolver without `@ip` hints is announced by name only (also in the RA), and this server answers the `_dns.<name>` SVCB query that follows. Multicast, loopback and unspecified addresses in `DNS_DDR` are refused (clients discard them). The layout was checked field by field against the figures and text of RFC 9463 sections 4 to 6. Limits: this app is not a DHCP server, it only produces the options; it was not tested against a real DHCP server or client (the dnsmasq `option6:` line and the Kea `code`/`space` entries follow their documentation from memory: check them with your version); the RA form is left out for a resolver with only IPv4 hints; a DoH entry takes its hints after the path (`doh:host/path{?dns}@ip`). Restart the daemon and gunicorn. The query log also shows the response code in each row.
- Query log, live refresh and hourly domain rollup (`DomainStat`, migration 0026): the page refreshed every 3 s with `setInterval`, so a slow request (the grouped view over a long period) was overtaken by the next one and they piled up on the server and the database. Now one refresh at a time, none while the browser tab is hidden, and the wait grows with the time the last refresh took (at least 3 s, three times the request). The list no longer reads the `answers` column of every row (it does not show it), and the grouped view over long periods reads the hourly `DomainStat` / `StatCount` counters instead of scanning millions of log rows.
- Public lists, faster with millions of domains. `import_blocklist` writes only what changed (domains added, removed or moved to another list) instead of deleting and re-inserting every row: on a test table of 1.3 million domains with 1% of them different, 8 s instead of about 84 s (SQLite; the transaction is small, so the table is not locked for long). Two composite indexes replace the two single ones on `source` and `list_name`: `(source, name)` and `(list_name, name)`, so the sorted, paged list (and a deep page: 0.48 s to 0.01 s) is read from the index and not sorted. The counts per list are cached and emptied by every import; no search = no count over the table; a search is counted up to 100000 and the admin search on public lists is "starts with". The table is **not** partitioned: the daemon reads it by exact name through the unique index, a partition would not shorten that, and the table fits in memory. Needs `manage.py migrate` (0022; it builds two indexes on a large table: do it at a quiet time).
- Blacklist, per list: every imported domain remembers its public list (`list_name`; the first list that has it). `BLOCKLISTS` takes `name=url` (a plain URL is named after its file). The query log says which list blocked a name (`blacklist ads.example (hagezi-tif)`, `(personal)`, `(pattern ...)`), and Public lists shows each list with its count (click a list name to see only its domains; the master switch turns all of them off). Existing entries get their list name at the next `import_blocklist`. Needs `manage.py migrate` (0021).
- Blacklist, patterns and temporary entries: a personal entry can be a regular expression (`regex`, matched with `re.search` on the queried name, e.g. `^ads?\d+\.`; a pattern Allow beats everything, a pattern block applies when no domain entry matched), and an Allow can last 1 hour, 1 day or 7 days (`expires`; ignored afterwards, up to `DNS_DATA_TTL` late). A bad pattern is refused (200 characters at most); a pattern with nested repeats is rejected to prevent ReDoS.
- `scan_trackers`: a domain whose chain ends on a tracking pixel (an image under 200 bytes, or an empty 204) and sets persistent / cross-site cookies is matched too, not only the ones that redirect to another domain.
- Blacklist: **exceptions** (Allow). In Personal blocks, next to Block, and from the query log (an Allow button on blocked rows and groups): the domain and its subdomains are never blocked by the public lists or by CNAME cloaking; the longest entry wins, so a block on a host inside an allowed domain still blocks it. A name that already sits in a public list can now be blocked or allowed by hand (the personal entry takes its place and the next import skips it). Needs `manage.py migrate` (0020).
- Blacklist: **suggestions**. Personal blocks lists up to 50 names asked for in the last 7 days that look like ads or trackers (a label such as `ads`, `track`, `pixel`, `telemetry`, `metrics`, or a domain registered less than 30 days ago according to RDAP), not blocked, not allowed, not in your zones, from the hourly counters (the 5000 most asked names), each with a Block button. A hint to confirm one by one. `GET /api/blocked/suggestions/?days=`.
- Blocking: `import_blocklist` loads several public lists at once and merges them (`BLOCKLISTS`, comma-separated URLs; default StevenBlack, OISD small, 1Hosts Lite and the HaGeZi lists Ultimate (includes Pro++/Pro/Multi/Light), TIF (threat feeds), Popup Ads, Fake and the native telemetry lists, about 1.3 million domains; category lists (social, gambling, nsfw, ...), VPN/DoH, hosters and dynamic DNS are not in the default; or pass URLs/files on the command line); if one cannot be downloaded the old entries stay. Run it nightly from cron (INSTALL.md now says so). CNAME cloaking: a forwarded answer whose CNAME chain points at a blacklisted name (`metrics.site.example` → `x.tracker.example`) is now blocked as well, logged as `cname <target> -> blacklist <entry>`. Restart the daemon.
- Statistics: each bar of the chart is split into executed (bottom) and blocked (red, top) queries, with a legend and a tooltip with both numbers; the number above the bar is still the total. API: every `series` entry has a new `blocked` field (`count` stays the total).
- GUI audit fixes (Lighthouse): contrast of the active zone, of the record type chips and of the outcome chips in the query log, meta description, a minimal `llms.txt`, no `box-shadow` transition on record rows. nginx example: `Content-Security-Policy` and `Cross-Origin-Opener-Policy` on the page, the cache rule for hashed files now also matches names with `-` or `_` in the hash (`chunk-IU9i2-jS.js`), and one day of cache for the logo, icons and map data. Copy `deploy/nginx/dns.example.lan` again and reload nginx.
- Query log: the total of the list is counted up to 100000 rows (a count over millions of rows ran on every page and every live refresh; above the cap the total shows 100000 and the paging still goes on), and the count of groups no longer sorts them.
- Geolocation: the map can be zoomed (mouse wheel, drag to pan, +/−/reset buttons). Each country has a "Show these queries in the log" button that opens `/logs?country=XX&hours=N`. New query log filter `country` (ISO code, `PRIV` or `??`; list and grouped): the domains whose answers pointed to that country in the period, from the `GeoStat` counters (a domain answered from several countries is listed whole; at most 5000 domains; `hours=0` uses 24 hours; addresses not yet located are not counted). The log page reads `country` and `hours` from the URL, shows a "Remove filter" notice and has a "Last 30 days" period.
- Geolocation: the AS name from Team Cymru is looked up once per AS (in-memory cache) instead of once per address, and `GET /api/geo/destinations/` is served from the cache (Redis when `REDIS_URL` is set) and recomputed in the background at most once a minute (and while lookups are pending), so a request does not wait for the aggregation or the network lookups; only the first request after a cold start computes it.
- Query log, grouped view: queries for the root (an empty name, e.g. `. NS`) were a group with no name, and expanding it listed every query because an empty filter is ignored. The group is now called `.`, can be expanded (`domain=.` / `name=.` select the root), and has no Audit or Block button.
- Query log details: a Whois button next to every public A/AAAA address (in the records of an answer and in the addresses a group resolved to) shows the WHOIS record from the regional registry. New `GET /api/geo/whois/?ip=`: asks `whois.iana.org` (port 43) which registry holds the address, then that registry (only ARIN, RIPE, APNIC, LACNIC and AFRINIC are followed); private and special addresses are refused; cached for a day. The server needs outbound access to TCP 43.
- Query log: the client filter is a text box with auto-complete over the distinct client IPs (most active first, at most 500; type an IP or a host name, shown without the zone), each shown with the FQDN of `DEFAULT_ZONE` whose A/AAAA record has that IP (also shown on the rows and in the query details). New `GET /api/logs/clients/` (`hours` optional) reads the hourly `client` counters, a few rows, not the log. IPv6 addresses are matched as text; with several names for one IP the shortest wins.
- DNS protocol conformance (RFC 1035, 2308, 4592, 6891): NXDOMAIN for blocked and suspicious names is no longer authoritative and carries an SOA (clients can cache it for `DNS_CACHE_NEG_TTL`); a static host's NODATA answer carries an SOA; a query with an EDNS OPT gets an OPT back, and the upstream cache key now includes EDNS, DO and CD (the cache refills by itself after the update); a UDP answer larger than 512 bytes, or than the size the client announced (at most 1232), is cut with TC=1 so the client retries over TCP; more than one question gives FORMERR, an opcode other than QUERY gives NOTIMP, a class other than IN gives REFUSED; a wildcard no longer covers a name that exists as an empty non-terminal. Restart the daemon.
- `manage.py import_asn`: nightly IP → ASN index built from ipverse/as-ip-blocks (BGP prefixes per ASN, CC0), used for the addresses that the ASN `.mmdb` lacks (about 1% of answers; they were filled by Team Cymru DNS lookups or stayed unknown). It streams the 17 MB archive without extracting it, flattens nested prefixes (the most specific wins) and writes a compact file (`ASN_INDEX`, 8 MB) that is searched in place and reopened by itself; if the download or the archive is broken the old index stays. `ASN_INDEX` (empty = off) and `ASN_IMPORT_URL`.
- Sign-in sessions last at most 2 hours (`SESSION_MAX_AGE`, 7200 s; absolute, not idle): the API token expires that long after the sign-in that issued it (the GUI returns to the sign-in page on the 401), and so does the Django admin session. Every sign-in issues a new token, so signing in on another device ends the user's older sessions.
- Query log partitioned by day on MySQL/MariaDB and PostgreSQL (`manage.py partition_querylog`, once; rebuilds the table, so run it at a quiet time and back up first): old days are dropped with `DROP PARTITION` / `DROP TABLE` instead of a huge `DELETE`, and `rundns` creates the next days' partitions every hour. The primary key becomes `(id, time)`. On PostgreSQL the table is replaced by a partitioned one (no default partition: the next 7 days must exist). SQLite is unchanged. The PostgreSQL path was written without a PostgreSQL server at hand: try it on a copy first.
- Statistics and geolocation read hourly counters (`StatCount`, `GeoStat`) kept up to date with every batch of log rows, instead of grouping the whole log: much faster on an external database. Windows over 2 hours start at the hour in which they begin; the per-minute view (up to 2 hours) still reads the log. Needs `manage.py migrate` (0019), then `manage.py rebuild_stats` once to count the existing log. Purging the log also purges the counters.
- Statistics: one scan instead of three for total, average and outcomes; the response is cached for 30 seconds.
- Fewer database round trips: geolocation cache saved with one `bulk_create` upsert instead of two queries per address; the daemon's reload reads both master switches in one query and records and hosts as plain values.
- Query log indexes on `name`, `(domain, time)` and `(outcome, time)`. Needs `manage.py migrate` (0018).

## 1.0.1 — 2026-11-08
- RFC 6303: reverse lookups (PTR) of private and special addresses (10/8, 172.16/12, 192.168/16, 100.64/10, 169.254/16, 127/8, `fc00::/7`, `fe80::/10`, `::1`) that no zone answers get NXDOMAIN from the daemon, with the `aa` flag and an SOA, and never go to the upstream (routers often answer SERVFAIL). `DNS_LOCAL_REVERSE=false` turns it off. A local reverse zone still answers first.
- Deleting a zone needs a second factor (authenticator code or passkey) from the already signed-in user, no password: step-up endpoints `/api/mfa/stepup/…` give a one-use grant (2 minutes, one zone) that `DELETE /api/zones/<id>/` requires in `X-MFA-Grant`. Users with no second factor are not asked.
- Zones can be switched off and on one by one (`enabled` flag; switch next to the zone name in the GUI, and in the Django admin): a disabled zone and its records are kept but not served, its names are answered as if the zone did not exist; the GUI shows its records as disabled and read-only. Needs `manage.py migrate` (0017).
- Master switch for the Public lists too (`GET`/`PATCH /api/blocked/public/`): off = the imported domains are kept but ignored and shown as disabled; the Personal blocks keep working. At once, no new migration beyond 0016.
- Master switch for the Personal blocks (GUI, top of the page; `GET`/`PATCH /api/blocked/personal/`): off = the blocks added by hand are kept but ignored, the imported public lists keep blocking. Takes effect at once. Needs `manage.py migrate` (0016).
- Personal blocks can be switched off and on (`enabled` flag, GUI switch and Django admin): a disabled block is kept but does not block. Needs `manage.py migrate` (0015).
- Internal zones are authoritative: a name missing from a zone gets NXDOMAIN, a name without that record type gets NODATA (empty NOERROR), both with `aa` and a generated SOA (RFC 2308) instead of going to the upstream; `SOA` queries at the zone apex are answered. **Behaviour change:** names under an internal zone that have no record are no longer forwarded; `DNS_AUTHORITATIVE=false` brings the forwarding back.
- A CNAME that points to a name in our own zones now also returns the target's records (e.g. `www CNAME @` answers with the apex A record).
- Zone records can be sorted by type, host, IP / value (IPv4 numerically, then IPv6 and names) or TTL, ascending or descending.
- Statistics: the chart follows the chosen period (per minute for the last hour, per hour for 24 h, per day for 7 and 30 days: 7 and 30 bars, today included, days in the browser's time zone), with empty buckets shown as zero. The stats API takes an optional `since`. API: `per_hour` replaced by `series` + `step`.
- Static hosts (like `/etc/hosts`): exact names answered with fixed IPv4/IPv6 addresses before zones, blacklist and upstream; GUI page, API (`/api/hosts/`) and Django admin; loaded in the in-memory/Redis copy and refreshed on every change. Needs `manage.py migrate`.
- Prefetch: cached answers that are about to expire and still asked for are renewed in the background (`DNS_PREFETCH*`); cached TTLs now count down.
- Query log written in batches by a background thread (`DNS_LOG_FLUSH`, `DNS_LOG_QUEUE`): answers no longer wait for the database write. Needs `manage.py migrate`.
- Persistent database connections: the DNS daemon uses a fixed pool of worker threads (`DNS_WORKERS`) that keep their connection open, `DB_CONN_MAX_AGE` and connection health checks for the API.
- One persistent, shared Redis connection pool per process (`REDIS_POOL_SIZE`): the daemon no longer opens a connection per query.
- Zones, records and blacklist answers stay in the DNS daemon's memory until the data changes (change counter in the database and in Redis, `DNS_DATA_CHECK`, `DNS_DATA_TTL`; with Redis a change shows at once and a restart is warm): fewer database reads per query. Needs `manage.py migrate`.
- Several upstream resolvers with failover (`UPSTREAM_DNS=a,b`), and stale answers served from the cache when all are down (`DNS_STALE_TTL`).

## 1.0.0 — 2026-11-07

First release of Zones.dns (backend and frontend share the version).

### DNS daemon
- Internal zones (forward and reverse) served from the database; everything else forwarded to `UPSTREAM_DNS`, with an upstream answer cache (Redis or in-process).
- Records of 13 types, wildcards, enable/disable, notes, zone file import/export, automatic PTR records.
- Query log with outcome, resolution path and answers; blacklist (personal blocks and imported public lists); suspicious-query filter (tunnelling, DGA, ANY/AXFR, subdomain scans).

### GUI (Angular 22)
- Zones, Blacklist, Query log, Geolocation (map), Domain audit, Statistics and Security pages; guided record form; English interface.
- Responsive layout for phones, tablets and landscape; lazy-loaded routes.

### Security
- Encrypted sign-in and second-factor steps (NaCl `crypto_box`, fresh server key at every start).
- Two-step sign-in with authenticator app (TOTP) or passkey; mandatory by default.
- Django admin opened only from the GUI, for superusers, with a one-use ticket.
- Weak `SECRET_KEY` refused with `DEBUG=false`.

### Operations
- API described in OpenAPI; generated Angular client.
- nginx virtual host (HTTPS, HTTP/2, HTTP/3).
- Commands: `rundns`, `import_blocklist`, `scan_trackers`, `mfa_reset`.
